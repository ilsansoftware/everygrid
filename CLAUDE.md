# CLAUDE.md

Guidance for working in this repo. Keep changes minimal and match surrounding style.

## What this is

**Everygrid** — a config-driven React data grid that offloads heavy data ops (filter/sort/paginate over millions of rows) to a Rust→WASM engine running in a Web Worker, so the UI never blocks. Published as `@everygrid/grid`.

## Monorepo layout (pnpm workspaces)

```
everygrid-wasm/        Rust engine → WASM. `GridEngine` struct = filter/sort/paginate.
  src/lib.rs             Single source; exposes wasm_bindgen methods (set_data, filter, sort, get_page…).
  pkg/                   GENERATED by wasm-pack. Linked into the grid pkg via `link:`. Do not hand-edit.
packages/everygrid/    The library `@everygrid/grid`.
  src/core/Everygrid.tsx   Main class (~1500 lines): lifecycle, DOM mount, state, autoInit.
  src/core/types.ts        Public config/option types (exported from index.ts).
  src/wasm/GridEngineWasm.ts    Main-thread proxy → posts to worker, awaits by seq.
  src/wasm/GridEngineWorker.ts  Runs WASM off the main thread. Imports `everygrid-wasm`,
                                which package.json maps to `link:../../everygrid-wasm/pkg`
                                — that linked pkg is the ONLY wasm copy either build uses.
  src/components/          React UI (toolbar, table, pagination, popups, excel view…).
  src/index.ts             ES-module public entry.  standalone-entry.ts = UMD entry.
demo/portal/           Single unified demo app (one vite project, one server, one build).
  src/                     React portal shell + React demo (consumes @everygrid/grid dependency).
  public/{vanilla,jquery}/ Static HTML demos, embedded as iframes. Their `<script src>` is the
                           `%EVERYGRID_STANDALONE%` placeholder, substituted by vite.config.ts.
  public/react/            Config + data JSON for the React demo.
scripts/deploy.sh      Build → npm pack → S3 + CloudFront invalidation.
```

## How it works (mental model)

1. `everygrid.config.json` (project root) lists grid config file URLs.
2. `Everygrid.autoInit(apiFetchers?, entryConfigUrl?)` fetches them, merges `targets`, and mounts a React grid into each DOM element whose `id` matches a target id.
3. Data-heavy work goes to WASM via `GridEngineWasm` (proxy) → `GridEngineWorker` (worker) → `GridEngine` (Rust). Each grid gets its own Worker.
4. Config is data-driven: pagination, editable cols, checkboxes, colors, compact mode are all per-target config objects (see `types.ts` and README table).

## Build & commands

| Command | Use |
|---|---|
| `pnpm build:wasm` | Rebuild WASM after **any `lib.rs` change**. Regenerates the linked `pkg`. Needs `wasm-pack` + cargo. |
| `pnpm build:everygrid` | Build ES module (`dist/index.js`). |
| `pnpm build:standalone` | Build UMD (`everygrid.standalone.js`) — inlines WASM base64, worker, and CSS into one file. |
| `pnpm build` | wasm → everygrid → standalone (full). |
| `pnpm lint` / `pnpm lint:fix` | ESLint over the whole repo (build outputs are ignored). |
| `pnpm test` / `pnpm test:watch` | Vitest. |
| `pnpm demo` | Run the unified demo portal (vite, port 4000) **and** the library in `--watch`, so a source edit reaches every tab. |
| `pnpm deploy` | Full build + `scripts/deploy.sh` (S3/CloudFront). Don't run casually. |
| `pnpm version:patch` / `version:minor` | Bump `packages/everygrid/package.json` — the single source of truth. See Versioning. |

**Where the demos get the library** (`demo/portal/vite.config.ts`) — local always runs your
workspace code; only the deployed site runs the published artifacts:

| | React demo (bundled) | vanilla / jquery (`<script>`) |
|---|---|---|
| `pnpm demo` | workspace **source** — HMR | workspace `dist/everygrid.standalone.js`, served at `/lib/` (kept fresh by the `--watch` half of `pnpm demo`) |
| `pnpm deploy` | `$EVERYGRID_PKG` — the **tarball** deploy.sh just published, unpacked | `$EVERYGRID_CDN` — the deployed standalone |

So a plain `vite build` (no env vars) falls back to the workspace, and `pnpm deploy` is the only
thing that exercises the published artifacts. If a demo tab shows stale behavior after a source
edit, check this table first — the vanilla/jquery tabs used to load the CDN build unconditionally,
which made local fixes invisible there.

**Two build formats** (`packages/everygrid/vite.config.ts`, switched by `BUILD_FORMAT=standalone`):
- **ES**: uses `vite-plugin-wasm`, emits `index.js`. For bundler consumers.
- **standalone UMD**: `wasmInlinePlugin` inlines the `.wasm` as base64, forces the worker to `?worker&inline`, and injects CSS — a single self-contained file for CDN/`<script>` use. If you touch worker loading or WASM init, verify both formats.

## Versioning

**Version and build identity are different things.** Every deploy publishes hash-named,
immutable artifacts (`/packages/everygrid-grid-<version>-<hash>.tgz`), so the exact bytes are
already addressable. The version is only a compatibility promise to humans — so it does **not**
move every deploy, only when the public API does. Repeat deploys of one version are fine; they
get distinct hashes. (Docker's `image:1.2` vs `image@sha256:…`.)

Public API = `src/index.ts` exports + `types.ts` config schema + the `everygrid.config.json`
contract + the `window.Everygrid` global.

While at `0.x`, npm's caret makes **MINOR the breaking slot** (`^0.1.2` resolves `>=0.1.2 <0.2.0`):

| Bump | When | Note |
|---|---|---|
| MINOR (`0.2.0`) | Breaking: an export or config key removed/renamed, changed meaning, changed `autoInit` signature | |
| PATCH (`0.1.1`) | Everything else — bug fixes **and** backward-compatible additions | Counter-intuitive, but a new feature is a PATCH while at 0.x; that is what keeps `^` honest |
| `1.0.0` | Declaring the API frozen | |

Don't use `0.0.x`: `^0.0.3` resolves `>=0.0.3 <0.0.4`, i.e. every release is breaking, which
throws away the only signal there is.

## Change-impact rules

- Edit `everygrid-wasm/src/lib.rs` → run `pnpm build:wasm`, else JS uses stale WASM. New `#[wasm_bindgen]` methods must be proxied in `GridEngineWasm.ts` and handled in `GridEngineWorker.ts`.
- New public type/API → export from `packages/everygrid/src/index.ts`.
- CSS lives in `src/styles/Everygrid.css` (Tailwind v4). Standalone injects it at runtime.
- `pkg/` and `dist/` are build outputs — never edit by hand.
- User-facing config/API changes → update `README.md`.

## Working methodology (token-frugal — the user requires this)

The user is cost-sensitive and repeatedly asks to conserve tokens. Apply:

- **Don't re-read a file to confirm an edit** — `Edit`/`Write` error on failure; trust success.
- **Minimize build/verify runs.** Prefer one targeted `tsc -b` or `pnpm build:wasm` at the end only when the change needs it. Skip speculative full builds.
- **Batch independent tool calls** in one message; avoid exploratory wandering — go straight to the file you need (layout above tells you where).
- **Grep with tight, scoped output** rather than reading whole large files (`Everygrid.tsx` is ~1500 lines — target the symbol).
- **Keep replies short**: what changed + why, a few lines. No long recaps or verification narration unless asked.
- Prefer editing existing files over adding new ones; don't create docs/README proactively.
